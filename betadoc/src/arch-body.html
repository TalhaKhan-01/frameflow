Architecture · the complete technical flow

The newsroom,opened up.

Frameflow runs on one laptop. A Telegram bot ticks every 30 seconds and moves each posting day through a small state machine. Long steps run as their own processes. Every step is a desk with a gate, and the gates sit before the one expensive step, the render. The model calls go through Claude Code inside a subscription, so there is no API key and no API bill. This page follows one story from the wire to the feed, and then back into the next video as lessons.

01 · The clock

A posting day is a state machine.

One row per posting day in SQLite holds its state. The bot runs daily tick every 30 s: at 14:00 it scouts tomorrow, at 15:00 it auto-picks if nobody tapped, at 11:30 it posts what was approved, and 48 h later it collects stats. Every long step is spawned as its own process with its own log, so the bot keeps answering while a video renders, and a restart resumes from the stored state.

  1. topic-sent14:00 · 15 candidates on the topic card
  2. pickedowner ticks 5–8, or the top 8 at 15:00
  3. makingdaily make spawned: brief → board → render
  4. video-sentvideo card: Approve · Revise · Reject
  5. queuedapproved; waits for the 11:30 slot
  6. postingpack → YouTube, Instagram, Facebook
  7. postedlinks back to Telegram, Studio refreshed
  8. +48 h statsstats → lessons → library → cleanup

side exits: revising → making (at most 2) · skipped · rejected (reason kept as a lesson) · failed (/retry re-runs the step)

02 · Intake

Hundreds of headlines, one ranked card.

ideas collect pulls five kinds of sources (research/sources.json) into data/frameflow.db, deduplicated by URL. ideas rank scores every fresh, unranked idea in one batched model call (score, lane, angle, hook), so ranking a day's wire costs about as much as one paragraph. The show's topic desk then ranks the day's candidates by virality and sends 15 to Telegram as toggles.

03 · Research and fact-check

Nothing unsourced reaches the script.

The researcher (brief.py) works with web search and fetch and returns facts that each carry the URL that supports them. Then code takes over, because a model can be confidently wrong:

  1. Re-fetch. Every source is loaded again. A fact whose page doesn't load is dropped.
  2. Floor. A brief with fewer than 8 sourced facts is refused.
  3. Independent check. The shorts-factcheck skill re-reads each page as text and rules on each fact from that text alone: supported, partly (with corrected wording), unsupported (dropped) or unreachable.
  4. Numbers in code. Later, every number the script says, in digits or in words, must be in the verified facts.

04 · The studio board

Seventeen desks, one render.

A make goes desk by desk, and each desk's gate must pass before the next desk starts. Fix loops are allowed only while a fix is still a text edit. After the delivery render nothing loops: the result goes to the owner with its honest numbers.

  6. 06 · shorts-directorDirectorOne visual metaphor per idea, motion timed to the spoken words, something new every 2.5 s, transitions by meaning, the SFX cue sheet.
  7. 07 · voice.py + precheck.pyNarratorRecords the real voice, times every word, then checks re-hook gaps, caption accuracy, length and voice start on it.↺ fails → one writer/director fix, re-voice (local, free)

  11. 11 · artdirect.pyArt directorMeasures the draft: no empty paper for a second, no black stretches, every still on the house palette.
  12. 12 · shorts-screeningScreeningA strict first viewer scores a contact sheet of the draft, row by row, and names where a viewer would swipe away.↺ below the bar → fix → back through the narrator
  13. 13 · build.py + pipeline.pyRender, onceThe delivery render: HyperFrames frames, the voice, captions, music ducked under the voice, loudness to −14 LUFS.
  14. 14 · qa.pyQCThe measurable rows of the Quality Bar as pass/fail gates on the file itself.
  15. 15 · bot.pyOwnerThe video card on Telegram. Nothing is published without the owner's tap.
  16. 16 · publish.py + pilot.pyPublisherCaptions per platform; Meta Graph API and The Pilot; links back to the card.
  17. 17 · analyst.pyAnalyst48 h later, ties every result to the decision that caused it: hook family, ending, length, package.

Why one render: before 26 Oct the pipeline rendered, reviewed, rewrote and rendered again. The second render cost as much as the first and scored worse (14/22 → 13/22). Fix rounds are bounded by the active profile (timing_fix_rounds, animatic_fix_rounds, 1 each on lean).

05 · The Daily Habit show mode

Eight stories, one episode.

With research/show.json enabled: true, the daily make runs show.py instead of one single-story Short. It uses the same desks in a rundown shape: one researcher per story (4 in parallel), a fact-checker per story, a writer for the open, one 20–32 word segment per story with a witty line, and the outro. Then come lints in code and an independent table read, with up to 2 doctor rounds. A director in code picks a framing pattern per topic and adds the countdown, graphics and Habit's emotions. 06 · The render engine

Six layers become one frame.

A video is a scene plan: JSON naming a template from 18 scene types for every line, the data it shows and the sources behind it. build.py turns the plan into a HyperFrames project (a root composition at 1080×1920 with one sub-composition per scene), and the renderer steps it frame by frame. Nothing depends on the wall clock, so the same plan gives the same file.

  1. Scene planscene_plan.py validates the contract; errors go back to the director's doctor once.
  2. Compositionsindex.html + compositions/s<N>.html, GSAP, bundled OFL fonts, the house theme.
  3. VoiceChatterbox "lively" on the GPU (seeded, so it can be repeated); Kokoro as the fallback. Each line's energy sets its expression.
  4. CaptionsLocal Whisper word timestamps → chunks of up to 3 words, each word lit as it is spoken.
  5. SoundA fixed SFX vocabulary on the cue sheet, a music bed ducked 7 dB under the voice.
  6. MasterLoudness to −14 LUFS, true peak under −1 dBTP; an asset ledger row per file.

07 · Quality gates

The file is measured, not admired.

One file, research/quality-bar.json, holds every number, and every desk reads it, so no two desks aim at different targets. bar calibrate re-measures the voice's real speed (2.89 words a second today) after each video and copies it to the writer and director. Below, a scanner passes over 12 real frames of the latest Short while the gates resolve.

  • Length≤ 95 s · target 75–90
  • Size1080 × 1920
  • Loudness−15 to −13 LUFS
  • True peak≤ −1.0 dBTP
  • Blackno stretch > 0.5 s
  • Blankno near-empty frame ≥ 1 s
  • Eventssomething new every ≤ 2.5 s
  • Re-hooksevery ≤ 10.5 s
  • Captionsword error < 10%
  • Voice startfirst word by 0.3 s
  • Licencesa ledger row for every asset
  • Coveronly numbers the script says

Then the judgement rows: hook, story, flow, persona and humour, visual storytelling, pacing, sound, captions, sources, honesty and ending, 0–2 each, by a model that sees stills and the script but never wrote them. The show passes at 80% of each maximum. A miss is not hidden: the card says what failed, and "Approve anyway" turns the failures into lessons.

  • Instagram ReelsMeta Graph API. If the token is dead, The Pilot posts it through the app instead.
  • Facebook PageMeta Graph API as the Page, with the same fallback. Carousels go the same way.

Every platform gets its own text from the social-caption skill: a title that holds the stake, a first line that stops the scroll, an honest comment question and a tag set per platform (Instagram's cap of 5 is respected). Code checks that no number goes beyond the script. Taps made while the laptop is off wait in Telegram and are handled at 10:00. On Revise, the owner writes in their own words; the showrunner turns them into a change order, and the order re-runs only the stages it touches, so a remark about the music never re-renders the video.

09 · The learning loop

Every video teaches the next.

  • Sources of lessons. Review rows, failed gates, the owner's /feedback and Reject reasons, and the 48 h stats.
  • The ledger. research/lessons.jsonl: one general lesson per line, with area (writer or director), evidence, and the counts seen, helped and hurt. Status is active, promoted or retired.
  • Into the prompts. The top 8 active lessons per area are written to lessons-writer.txt and lessons-director.txt, which the skills read as house rules.
  • Promotion. On Sunday, lessons that helped three or more videos are offered as permanent house rules.
  • The library. After the stats, library.py keeps what a video made but didn't use (spare hooks with scores, sourced facts, analogies, scene ideas). The researcher starts from it and re-checks every fact. Then cleanup.py frees the bulky files.
  • The analyst. One row per video in data/analyst.jsonl, grouped by decision (hook family, ending, lane, length, package), so the next make can see what actually worked.

10 · Model routing

The big model only where quality is decided.

Every call goes through llm.py: claude -p with no tools unless asked, no project settings, a short system prompt and structured JSON out. Token usage is appended to data/llm-usage.jsonl, so the cost of every video can be measured. Presets live in research/profiles/ (diet, lean, quality); frameflow profile use switches them and can be undone. This is lean, the one in use:

Opus high effort

  • script draft
  • storyboard
  • animatic screening
  • show writer + judge

Sonnet medium effort

  • research brief
  • hook room + judge
  • every fix round
  • post captions
  • show research + virality

Haiku small jobs

  • idea ranking
  • cover title
  • lesson distilling
  • card post text

Measured, not guessed: most of a fix round's output was the model thinking (60k tokens to change a few scenes), so fixes moved to Sonnet at medium effort. A usage limit pauses the step and re-runs it after the reset.

11 · Infrastructure

Four processes, two static sites.

frameflow-botTelegram long polling (no webhook, so no public URL) and the 30 s daily tick. Spawns every long step as its own process.
frameflow-chromeThe Pilot's dedicated Chrome, signed in to the platforms, DevTools on localhost only; waits for the display at boot.
frameflow-controlA local control panel with the same functions as the bot, plus a live Making panel fed by progress.py.
phasedoc-frameflowThe build cockpit: every task in the plan with an acceptance test that has actually run.

All four run under a process manager that restores them at boot and restarts them after a crash. Python runs in one uv environment; Chatterbox runs in a throwaway environment of its own because PyTorch is too heavy for the project. Secrets live in one mode-600 file outside the repository.

From the laptop to the web

  1. web exportsnapshot of runs, videos, lessons, library, build
  2. open | lockplain studio.json, or AES-GCM studio.enc (PBKDF2-SHA256, 600,000 rounds)
  3. git pushonly web/public and betadoc/public
  4. Vercel × 2Studio + this betadoc, built on every push
  5. browserlocked mode: the PIN derives the key and decrypts in the page

Only media that is already public is copied. Paths, tokens and chat ids never leave the machine. scripts/deploy-check.sh waits for the Vercel build of HEAD and probes the live site.
